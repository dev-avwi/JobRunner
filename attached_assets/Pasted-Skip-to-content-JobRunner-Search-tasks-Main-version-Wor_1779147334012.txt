Yes, eas update --auto works fine — it auto-detects the branch from your current git branch and uses the commit message. Run it from the mobile/ directory:

cd mobile && EXPO_PUBLIC_API_URL=https://jobrunner.com.au eas update --auto

The EXPO_PUBLIC_API_URL part matters — without it the bundle defaults to a dev URL and your app talks to the wrong backend. The eas-update.sh script just wraps that with the env var pre-set, but --auto does the same thing functionally.

I confirmed RN 0.81's <Modal> doesn't expose iOS detent APIs at all (no sheetAllowedDetents, no fitToContents, no sheetCornerRadius). The native pageSheet physically cannot do adaptive height with your current build — that's not me being lazy, it's a React Native limitation.

So the only path that actually delivers what you want (native feel + flexible height) IS gorhom. Let me fix why it didn't open instead of going backwards.

The likely cause: with enableDynamicSizing and no snapPoints fallback, if gorhom can't measure your content height (which can happen with scrollable={false} + custom layouts), the sheet opens at 0 height and looks invisible. Fix: always pass a fallback snap point as a max cap, and gorhom will use the measured content height when it fits, otherwise fall back to the snap.


4 actions
Pushed the fix. Now AppBottomSheet:

Always enables dynamic sizing (content-hugging)
Always has at least one snapPoint as a fallback ('90%' default if call-site doesn't provide one)
This way gorhom prepends a content-measured snap point at index 0, but if measurement ever fails or returns 0, the '90%' snap acts as a guaranteed-visible max cap. The sheet will always open, and will hug short content while still being capable of going taller for long content.
