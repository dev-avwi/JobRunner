FINAL SUMMARY
═══════════════════════════════════════════

Top 5 things truly ready to ship

Stripe payments + subscriptions + Connect payouts — webhook signatures verified, both managed-connector and env-var paths supported, live/test mode handled.
Twilio SMS + voice — webhook signatures validated server-side via the SDK; rate limiting around messaging endpoints.
Vapi AI receptionist — full assistant provisioning, signed webhook with timing-safe equal, dedicated /api/vapi/webhook endpoint.
Mobile dark mode — system-wide, system/light/dark modes with dynamic brand colours.
Mobile offline mode for core entities — SQLite-backed sync queue covering jobs, clients, time entries, chat (optimistic), and WHS docs.
Top 5 that LOOK ready but have hidden gotchas

Subscription gating — IS_BETA = true (server/freemiumService.ts:5) silently bypasses every paywall in 8+ places. Looks like billing works, but no one is being limited today.
Pricing displayed on mobile — Team shown as $99 and Business shown as $199 (mobile/app/more/subscription.tsx:559), but the server has Team at $59+$29/seat and no Business price at all. Customers will see one price and be billed another (or not be billable).
Stripe price IDs — none hardcoded; everything is dynamic price_data. Works, but you have no source-of-truth mapping in code, and no Stripe Dashboard products tied to your tiers.
Apple IAP — client SKUs exist and finishTransaction is wired, but no server-side App Store Server Notifications handler. Refunds, billing-retry events, and subscription state changes from Apple won't reach your DB.
Tap to Pay — code shipped, SDK installed, but isSDKAvailable = false is hard-coded pending Apple Case-ID 18817353. Anyone tapping the button gets the "temporarily unavailable" string.
Top 5 things still genuinely unfinished

server/routes.ts is 51,519 lines — single-file backend monolith ~17× the recommended cap. Cold start, code review, and onboarding all suffer.
1,185 TypeScript errors in tsc --noEmit. The build runs but you've lost all the safety TS is supposed to give you.
Hardcoded *.worf.replit.dev URL in mobile/src/lib/api.ts:22 — will ship into a production mobile build unless overridden by EXPO_PUBLIC_API_URL.
File uploads still mocked — server/routes.ts:9398 notes "we'll use a data URL or mock it" instead of S3/GCS. Stuffing files into data URLs hits DB and bandwidth limits fast.
MYOB and QuickBooks have no webhook verification / inbound webhooks — sync is one-way (push to vendor). Status updates done in MYOB/QBO will not reflect back into JobRunner.
Bonus brutally-honest call-outs

Web booking page (WebsiteAddon.tsx) has no mobile equivalent.
AI Receptionist screen still polls every refetchInterval rather than subscribing via WebSocket.
Helmet CSP in production still allows *.replit.dev and *.repl.co — fine for hybrid hosting, worth tightening once you're 100% on jobrunner.com.au.
Want me to fix any of the above? The first three I'd tackle in order are: (1) flip IS_BETA and reconcile mobile pricing strings with PRICING, (2) remove the hardcoded worf URL from mobile/src/lib/api.ts, (3) add an App Store Server Notifications endpoint so Apple IAP state stays in sync.
