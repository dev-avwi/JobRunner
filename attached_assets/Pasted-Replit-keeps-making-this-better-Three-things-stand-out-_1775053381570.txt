**The coordinate problem is the one nobody had fully solved**

This is the most important new insight in Replit's entire response. When Claude analyses a screenshot and says "button at bottom centre has a problem" — how does that become a precise SVG annotation drawn at the right coordinates?

The answer is in the prompt. You need to explicitly ask Claude to return bounding box coordinates as percentages of the screenshot dimensions. Not text descriptions. Actual numbers.

The JSON Claude returns needs to look like this:

```json
{
  "issue": "CTA button label is ambiguous",
  "severity": "critical",
  "bbox": {
    "x": 0.42,
    "y": 0.78,
    "width": 0.18,
    "height": 0.06
  }
}
```

Percentages not pixels because the screenshot might be 1280x800 but the video player renders at 780x490. Percentages scale correctly to any display size automatically.

Replit's honest note — Claude's spatial reasoning is decent but not pixel perfect. You might get coordinates 20-30px off. For a hand-drawn annotation style that's actually fine and might even feel more natural. But if the circle lands on the completely wrong element that destroys trust immediately.

This needs to be tested in week zero alongside prompt quality. Not just is the feedback useful — is the bbox accurate enough to land on the right element.

**The annotation timing solution is elegant and simple**

Replit solved this clearly. During Playwright replay, record the video timestamp when each new screen appears. Claude analyses each screenshot and returns issues with coordinates. When composing playback you have a simple map — screen 3 appears at timestamp 00:24, Claude found issues on screen 3, so at 00:24 plus a 1 second delay, trigger the SVG animations at the returned coordinates.

It works exactly like subtitle tracks in a video player. A sorted list of annotation events with timestamps. As the video plays, check currentTime against the event list and trigger animations when the timestamp matches. The HTML5 video timeupdate event fires frequently enough for smooth timing. This is genuinely simple once the batch architecture is in place.

**The extension trust barrier is real**

15-20% of users will hesitate to install a Chrome extension. That's not a small number. Your onboarding needs to be crystal clear — what the extension accesses, what it doesn't, why it's needed. One sentence that does the job: "The extension records your clicks and scrolls on your own tab. It cannot access any other tab, any passwords, or any data outside the recording session."

Replit's bookmarklet idea for V1.1 is worth keeping. Zero friction, less capable. Offer both and let users choose. Some will prefer the extension for accuracy. Some will try the bookmarklet first. Either way they're in the product.
