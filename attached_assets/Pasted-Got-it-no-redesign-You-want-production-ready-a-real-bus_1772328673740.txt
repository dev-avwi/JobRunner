# ✅ Production Readiness Checklist (Mobile + Backend)

## 1) Auth + Security (must)

* Token refresh + expiry handling
* Secure storage (no tokens in AsyncStorage if avoidable)
* Role-based access (owner/admin/worker)
* Server-side validation for EVERYTHING (never trust client)
* Rate limits + basic abuse protection
* Sensitive data redaction in logs

## 2) Data Integrity (must)

* Strong database constraints (unique IDs, foreign keys, status enums)
* Idempotency for critical actions (creating invoices, payments)
* Prevent duplicates if user taps twice or network retries
* Transaction safety for multi-step updates (job complete → timer stop → invoice draft)

## 3) Offline + Bad Internet behavior (critical for tradies)

* App works with no signal:

  * view job list + job details cached
  * add notes/photos queued
  * timer events queued
* Sync engine:

  * retry with exponential backoff
  * conflict resolution rules (last write wins OR server merges)
  * “Sync status” indicator (quiet but visible)
* “Optimistic UI” with rollback if server rejects

## 4) Performance (must)

* Fast first load
* FlatList virtualization (no lag)
* Image compression + upload in background
* Avoid huge re-renders (memoization, proper state slice)
* Pagination everywhere (jobs, invoices, clients)

## 5) Reliability + Crash handling (must)

* Global error boundary
* Friendly error UI (“Something went wrong. Retry.”)
* Network timeout handling
* Graceful degradation (features disable instead of crash)
* Background task safety (location, uploads)

## 6) Observability (non-negotiable for real businesses)

* Crash reporting (Sentry is common)
* Event logging (key actions: create job/invoice/payment)
* Audit trails for business-critical events
* “Support bundle” export (device info + logs + last sync time)

## 7) Payments + Finance safety (high stakes)

* Never trust client amounts — server calculates totals
* Payment recorded vs payment processed must be clearly separated
* Reconciliation-friendly records (status, timestamps, references)
* GST rules consistent
* No double-charging / double-recording (idempotency keys)

## 8) Permissions + Location (if using tracking)

* Clear permission flow
* Handles “Allow once” / “While using” / “Always”
* Background location requirements documented in-app
* Battery safeguards + adjustable tracking frequency

## 9) Deployment + Updates

* EAS Build (production)
* EAS Update strategy (staged rollouts)
* Versioning + changelog
* Environment separation:

  * dev / staging / production
  * separate API keys + databases

## 10) Legal + Business basics

* Terms + privacy (especially location tracking)
* Data retention rules
* Backup strategy
* Admin export (CSV/PDF)
