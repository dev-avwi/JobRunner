Thank you for the detailed review.

We have identified and resolved the issue you reported with the in-app purchase flow on iPad.

Root cause
Our backend endpoint that verifies Apple receipts (/api/subscription/verify-apple-receipt) was missing in production. The StoreKit purchase itself completed successfully, but when the app called our server to activate the subscription, the server returned 404. The loading indicator never cleared because no response ever arrived. Additionally, all three subscription buttons shared a single loading state, which is why every tier appeared to spin.

Fixes shipped in build 30 (version 1.1.1)

Server: Added the missing receipt verification endpoint with full Apple verifyReceipt integration, including the sandbox fallback (status 21007) so reviewer test accounts behave identically to production accounts.
Client: Replaced the shared loading state with per-tier state, so only the tapped subscription button shows a spinner.
Client: Added a 90-second safety timeout that clears the spinner and shows a recovery dialog if the server is ever unreachable, so the UI can never get permanently stuck again.
Server: Implemented App Store Server Notifications V2 webhook to handle renewals, cancellations, refunds, and revocations.
The IAP flow has been re-tested in sandbox on both iPad and iPhone with all three subscription tiers (Pro, Team, Business). Purchases now complete in 2-4 seconds and the subscription tier updates immediately.
