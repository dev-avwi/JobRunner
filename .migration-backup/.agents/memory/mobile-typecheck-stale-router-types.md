---
name: Mobile typecheck vs stale expo-router types
description: Why mobile/scripts/typecheck.sh flags a brand-new route as a regression, and how to clear it
---

Adding a new screen file under `mobile/app/**` makes `router.push/replace('/(group)/new-route')`
fail typecheck with TS2345 ("not assignable to ... Href"). The route is valid — the typed-routes
file `mobile/.expo/types/router.d.ts` is generated by the Expo dev server, not by `tsc`, so it is
stale until the dev server regenerates it.

**Why:** `.expo/types/router.d.ts` is gitignored and only rewritten on `expo start` / dev-server boot.
The baseline guard (`bash mobile/scripts/typecheck.sh`) runs `tsc` against whatever is on disk.

**How to apply:** before running the typecheck guard after adding/renaming a route, regenerate the
types by briefly booting Expo, e.g. from `mobile/`:
`timeout 75 npx expo start --offline --no-dev --port 19009 &` then poll until the new route name
appears in `.expo/types/router.d.ts`, then kill it. Do NOT cast the path to `any` to silence it —
that hides real route typos. (CI has no typegen step and `.expo` is gitignored, so this is a
local-only artifact; don't try to commit the generated file.)
